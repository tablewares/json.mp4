# Things to avoid

- Don't write/edit files under `studio/manifest/**` directly — go through `init`/`add-scene`/`add-asset`/`update-asset`/etc. Only sanctioned `studio/` edits: component + manifest authoring for brand-new asset/transition type (see `validate-render.md`), plus three documented raw config/manifest fields with no CLI yet — `music` (`manifest.json`), `ttsHumanize` and `postEffects` (`config.json`), each described as sanctioned exception in its own section of `audio.md`/`post-effects.md`. Never hand-edit a project's scene/theme/config for anything else.
- Don't read files under `studio/manifest/**` (including `studio/manifest/example-project/` and `studio/manifest/boilerplate-toon/`) to learn how a scene is shaped, what fields an asset accepts, or what a project looks like. Use `show` to inspect an existing project you're editing; `asset <Type>`/`transition <Type>` for schemas.
- Don't fire long chain of individual `agent-cli.mjs` calls when you already know the whole sequence — use `scripts/agent-batch.mjs` once past two or three commands.
- Don't guess an asset's current id or scene's current transition before editing — run `list-assets`/`list-transitions` first.
- Don't invent asset or style keys. If `asset <Type>` doesn't list a key under `content` or `style`, that component doesn't read it — check command output, not memory of similar-looking asset.
- Don't skip `validate` before `render` on anything non-trivial — failed render subprocess far more expensive to debug than a validate error.
- Don't use `exitAt < 1` on an asset meant to ride full scene's narration. Asset visually disappears at `exitAt * sceneDuration`, which can land *before* scene's TTS audio finishes — leaving last word(s) playing against empty board. Reserve `exitAt < 1` for assets you explicitly want to leave early; for closers/narration-riders use default `1` (or omit `exitAt`).
- Don't assume TOON. This CLI writes plain JSON project files, which pipeline reads identically to hand-authored `.toon` — no extra step, nothing here requires `@toon-format/cli` conversion flow. (If curious, `docs/agent-guide/recipes/toon-manifest.md` covers per-file swap; never required.)
- Don't treat `overlap_warn.js` output from `render` as validation failure. Warns, never blocks — if `render` succeeds despite warnings, expected. Read as sanity check, fix the ones flagging real problems, don't edit `overlap_warn.js` to silence. (See `post-effects.md`.)
- Don't invent design criteria when none supplied. If run gives no external design context (palette, typography, scene cadence, asset choices), ask the user. This skill deliberately encodes no defaults for those.
- Don't hand-walk `studio/assets/**`, `studio/graphics/**`, or `public/assets/**` to "see what's available" before adding images/audio/SFX to a scene. That's a strong tendency and it's the wrong move: folder-walking tells you filenames, not what each asset expects or how to source more. Use the collection workflow via the CLI instead — `node scripts/agent-cli.mjs collections` lists every asset-library workflow; `node scripts/agent-cli.mjs collection <Name>` gives the exact command, destination, and output fields for one (e.g. `image`, `youtube`, `ytdlp`, `sfx`, `manifest`). Discovery through the CLI is authoritative; folder-browsing is a trap. Same for transitions: `node scripts/agent-cli.mjs transitions`, not `ls studio/transitions/`.
- For Yandex image search (`collection image` / `imageSearch`): results from `opencli yandeximages search` are URLs only — Yandex frequently returns captcha walls, redirect-to-CSS placeholders, or stale `img_url`s that 404. Never trust the JSON shape as proof of a downloadable image. Before using a result, run a connection test: actually `curl -fsSL` one `image_url`, then `file` the output to confirm it's a real image (PNG/JPEG/AVIF with real dimensions), not an HTML error page. If the test fails (HTML/text/empty), re-run the search with a higher `--limit`, or trigger a captcha solve via `opencli browser open <yandex-url>` and retry. See `04-images-opencli.md` for the full connection-test flow.
