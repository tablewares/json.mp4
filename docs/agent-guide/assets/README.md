# assets/

Two concerns, kept separate:

1. **Using an existing asset** in a scene — see `using-assets.md`. This is
   what you do 90% of the time.
2. **Adding a new asset component** to the framework — see
   `authoring-new.md`. Do this only when no existing asset fits.

The reference for the shape of an asset entry inside a scene file lives in
`../reference/asset-spec.md` (the authored JSON). This folder covers the
asset *component* side: what manifests declare, what shipped assets accept,
and the contract a new asset's component must satisfy.
